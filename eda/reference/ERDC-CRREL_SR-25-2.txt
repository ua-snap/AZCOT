Abstract 
Environmental parameters for operational planning in extreme 
conditions require accurate knowledge of prevailing meteorological 
conditions. However, the Arctic region presents unique challenges due to 
limited observational data and unique geographical conditions. To 
address the need for such knowledge, this study presents an analysis of 
Arctic prevailing- conditions using  European Center for Medium -Range 
Weather Forecasting ( ECMWF) Reanalysis v5 ( ERA5) Data from 1991 to 
2020. A custom Python -based framework was developed to process and 
analyze hourly datasets, identifying zones of extreme events and their 
frequency across multiple temporal scales. The framework uses ArcPy to 
automate the generation of nearly 40,000 mapped classifications for 
land masses 60°N and above. This automated pipeline enables both 
static and dynamic map generation capabilities for operational planning 
now and in the future. The resulting dataset provides critical spatial and 
temporal resolution of Arctic prevailing- conditions, enabling more 
refined characterization of extreme prevailing -conditions across the 
circumpolar region .

1 Introduction 
The US Army Engineer Research and Development Center–Cold Regions 
Research and Engineering Laboratory (ERDC-CRREL) is involved in 
several cold-weather operations, including the development of 
infrastructure and the planning of missions in extreme weather. This 
dataset provides information regarding the prevailing conditions across 
the Arctic as well as details of extreme events, including how extreme they 
are, how frequently they occur, and how long they occur for within a given 
day. The final data products are derived from gridded (0.25° × 0.25°) 
ECMWF (European Center for Medium-Range Weather Forecasting) 
ERA5 (ECMWF Reanalysis v5) reanalysis data and are available as 
GeoTIFFs, ArcGIS Pro Layer Files, or PDFs. 
This document details the dataset, including how each file was created, the 
process for designing the maps, automation techniques in Python, a user 
interface for creating new maps at custom time intervals, and the storage 
of the data. 
1.1 Dataset Product Name and Keywords 
The dataset product is developed as Arctic Zonal Characterization Maps 
and Data. The specific keywords providing parameter names and 
definitions are as follows:

1.2 Data Temporal Extent 
The dataset includes data from 1991 to 2020 during the winter months 
(October–March), starting with January 1991 and ending with December 
2020. The original ERA5 dataset contains hourly data for each 
meteorological variable, and the observational dataset contains 
meteorological data recorded between January 1991 and December 2020, 
although not all stations have the complete 30 years of data. 
Finalized maps and their associated files are broken up into six different 
static timescales shown in Table 1.

An example of data at different intervals can be seen in Figure A-1 in the 
Appendix. In addition to the static timescales above, the user interface 
allows for dynamic definitions of timescales (Section 6). 
1.3 Data Geographic Extent 
The ERA5 data were collected for latitudes greater than or equal to 60°N 
across all longitudes. All meteorological variables have a spatial resolution 
of 0.25° × 0.25°, with the exception of snow depth (derived from ERA5 
land data) which has a spatial resolution of 0.10° × 0.10°. 
1.4 Data Types 
Data files include NetCDF files (.nc), GeoTIFF files (.tif), ArcGIS Pro layer 
files (.lyrx), and PDF files (.pdf). Python code can be found as Python files 
(.py) or Jupyter Notebooks (.ipynb). The user interface directory also 
contains shapefiles (.shp) and ArcGIS Pro files (.aprx).

2 Data Acquisition and Preprocessing 
The data acquisition process is described in Section 2.1 of the Technical 
Report, Arctic Zonal Characterization and Operation Thresholding, and 
mirrors parts of this section.2 Readers should refer to the technical report 
for additional details. 
2.1 Shapefiles 
Shapefiles for the arctic countries and the geographic lines were obtained 
from Natural Earth (https://www.naturalearthdata.com/) in June 2024 for map 
design and data clipping purposes (Natural Earth 2024b). 
2.2 Reanalysis Data 
Data were subset for latitudes between 60° to 90° North latitude to cover 
all Arctic regions. The data were obtained from the ECMWF Data Store 
(also known as Copernicus) (ECMWF, n.d.-a). The site provides free 
access to a variety of ECMWF maintained datasets; it allows both manual 
downloads and a Python application programming interface (API) for 
more advanced data acquisition. The ERA5 data were initially obtained 
from ECMWF in gridded binary (GRIB) format. GRIB is a format based on 
standards established by the WMO and is typically used by operational 
centers that produce numerical weather prediction (NWP) output. All 
parameters were downloaded in a single hourly GRIB formatted file. 
Parameters selected include 2T, SKT, 10U and 10V wind components, 
SWE, and STL1. Additionally, at the request of stakeholders, snow depth 
was obtained from a derivative ECMWF dataset known as ERA5-Land 
(ECMWF, n.d.-b). This dataset provides higher spatial resolution at 0.1° 
(approximately 9 km) at the expense of noninclusion of data over oceanic 
and other water surface areas. 
Each GRIB file with multiple parameters was split into an individual 
parameter GRIB file using the open source wgrib software utility available 
from NOAA (NCEP 2005). On parameter separation, each separated 
parameter GRIB file was then converted into Network Common Data 
Format (netCDF) format in an effort to increase compatibility with other 
data processing applications. The conversion was performed by the open-

2.3 Meteorological Aerodrome Report (METAR) Data 
At the recommendation of project stakeholders, additional meteorological 
point observational data were obtained to provide limited verification of 
reanalysis data in key locations. These real-time observations are available 
in the International Civil Aviation Organization (ICAO) standardized 
Meteorological Aerodrome Report (METAR) format (ICAO 2021). Typically, 
each station reports meteorological parameters at a minimum of hourly 
thresholds, often through automated means. Thirty of years of METAR 
observations were obtained for stations within the area of interest. In some 
cases, certain stations were not available for the entire period due to 
budgetary and technological considerations of the individual countries 
provided the observations. 
Once the raw METAR observations were obtained, an initial processing of 
the data were undertaken using the open-source Python-METAR software 
suite (Pollard 2018). Data were processed to extract temperature, dew-
point, visibility, wind speed and cardinal direction, and current weather 
observed at time of observation in a comma-separated value (CSV) format. 
@@@ PAGE 20 @@@
ERDC/CRREL SR-25-2 10 
 
Additionally, a date-time code was also included which allowed METAR 
observations to be more easily combined for the purposes of generating 
time series statistics. Afterwards, the data were parsed using Python and 
converted to a data frames for further processing. 
METAR data were processed and aggregated from 370 stations in high-
latitude regions from 1990 to 2020. The database includes measured data 
from 12 different countries: Belgium, Canada, Denmark, Finland, Great 
Britain, Greenland, Iceland, Netherlands, Norway, Russia, Sweden, and 
the United States. The extent of spatial and temporal range and volume of

metric data to a larger timescale, the average of the relevant files was 
found. To aggregate the extreme metric data, the minimum/maximum 
across the relevant files was calculated.

respective biases of −0.7467°F and −2.1674°F (Table 7). This is expected,

surface temperature is expected to be colder. The correlation coefficient 
between the METAR and ERA5 wind speed was r = 0.7414 with a bias of

variables but still moderately strong (Table 7). Figure 2 shows the monthly

shapefile (Section 3.1) and an analysis extent of −180°—180° longitude, 
60°N—90°N latitude (Esri, n.d.-b). 
5.2 Symbology 
The symbology was developed based on iterative feedback from the 
stakeholders to be both accessible and informative. For temperature, 
warm colors were chosen to represent warm temperatures and cool colors 
represent colder temperatures. For wind and snow, warm colors represent 
dangerous conditions while cool colors represent more moderate 
conditions. Layer files were created from GeoTIFF files and a series of 
template layer files using the Apply Symbology from Layer tool 
(arcpy.management.ApplySymbologyFromLayer) (Esri, n.d.-a).

14. ABSTRACT 
Environmental parameters for operational planning in extreme conditions require accurate knowledge of prevailing meteorological 
conditions. However, the Arctic region presents unique challenges due to limited observational data and unique geographical conditions. 
To address the need for such knowledge, this study presents an analysis of Arctic prevailing-conditions using European Center for 
Medium-Range Weather Forecasting (ECMWF) Reanalysis v5 (ERA5) Data from 1991 to 2020. A custom Python-based framework 
was developed to process and analyze hourly datasets, identifying zones of extreme events and their frequency across multiple temporal 
scales. The framework uses ArcPy to automate the generation of nearly 40,000 mapped classifications for land masses 60°N and above. 
This automated pipeline enables both static and dynamic map generation capabilities for operational planning now and in the future. The 
resulting dataset provides critical spatial and temporal resolution of Arctic prevailing-conditions, enabling more refined characterization 
of extreme prevailing-conditions across the circumpolar region.
